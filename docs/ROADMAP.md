# Roadmap

The roadmap is a plan, not a claim of completed adoption.

## Phase 1 — Define

- Publish governance, contribution and accessibility policies
- Validate component requirements with Deaf users and educators
- Confirm package APIs and browser support
- Create public issue labels and decision records

## Phase 2 — Alpha

- Caption player with WebVTT, transcript and sign-video layouts
- Visual alert, progress and timer components
- ISL media metadata and validation helpers
- Unit, accessibility and browser test foundations
- Documentation and demo application

## Phase 3 — Beta

- Pilot integrations with at least two real products or programmes
- Performance and lower-bandwidth testing
- Theme and localisation guidance
- Public accessibility findings and known limitations
- Contributor onboarding and good-first-issue programme

## Phase 4 — 1.0

- Stable APIs and migration policy
- npm packages with release provenance
- Complete API and adoption documentation
- Browser support statement
- Maintainer and release process
- Public case study based on consented evidence

## Later candidates

- Framework adapters
- Web Components
- Caption authoring and validation utilities
- Additional sign-language metadata profiles
- Accessible live-event patterns

Candidate work must pass community review before entering a release plan.
